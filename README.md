# Университет RAG

Небольшая система Retrieval-Augmented Generation (RAG), которая отвечает на вопросы о ваших собственных документах и сообщает вам **откуда** пришел каждый ответ.

Поместите файлы PDF, DOCX и XLSX в папку, проиндексируйте их один раз, а затем задавайте вопросы на русском или английском языках. Ответы генерируются только из извлеченных фрагментов и цитируются их источники (файл + страница / раздел / лист и строки).

> **Статус:** рабочий MVP. Количественная оценка (качество изыскания, размер кусков и сравнение моделей) является следующей вехой, см. [Путожная карта](#дорожная карта).

## Как это работает

```

PDF / DOCX / XLSX

|

Загрузчики ----> Chunk(текст, источник, местоположение)

|

Чанкинг (около 1000 символов, 150 перекрытий, словосознание)

|

Встраивание (многоязычная база e5, работает локально на процессоре)

|

ChromaDB (постойкая, косинусное сходство)

|

Вопрос --> вставить --> фрагменты top-k

|

LLM (любой OpenAI-совместимый API) --> ответ с [1], [2] цитатами

```

Варианты дизайна:

- **Один общий формат. ** Каждый загрузчик возвращает один и тот же объект `Chunk(text, source, location)`, поэтому остальная часть конвейера не заботится о типе файла. Новый формат - это один новый файл плюс одна строка в `LOADERS`.

- **Загрузка с форматом. ** PDF делится по страницам, DOCX по заголовкам (таблицы становятся отдельными фрагментами), строки XLSX превращаются в читаемый текст, такой как `Субъект: Физика; Комната: 202` и группируются в 10 строк с диапазоном строк Excel, сохраняемым в качестве местоположения.

- **Локальные встраивания.** `intfloat/multilingual-e5-base` работает на процессоре ноутбука (без графического процессора, без платы за встраивание API) и поддерживает русский и английский языки. Требуемые префиксы `query:` / `passage:` добавляются автоматически.

- **Независимый от производителя LLM. ** Поколение использует API чата, совместимый с OpenAI, поэтому провайдер меняется на три переменные среды, а не на код.

- **Обоснованные ответы. ** Подсказка указывает модели использовать только извлеченные фрагменты, цитировать их и говорить об этом, когда документы не содержат ответа. Температура равна 0.

## Быстрый старт

Требования: Python 3.10+ (разработано на Python 3.12, Linux), около 3 ГБ свободного места на диске для зависимостей и модели встраивания.

```баш

Git clone https://github.com/el2006darr-cmyk/University-RAG-project.git

Cd Университет-RAG-проект

Python3 -m venv .venv

Источник .venv/bin/activate

# Сначала PyTorch только для процессора (избегает пакетов графического процессора с несколькими ГБ), а затем остальные

Pip install torch --index-url https://download.pytorch.org/whl/cpu

Pip install -r requirements.txt

```

Настройте поставщика LLM:

```баш

Cp .env.example .env

```

Отредактируйте `.env` и заполните три значения из документации вашего поставщика:

```

LLM_API_КЛЮЧ=

LLM_BASE_URL=

LLM_МОДЕЛЬ=

```

Работает любая конечная точка, совместимая с OpenAI (оставьте `LLM_BASE_URL` пустым для самого OpenAI). `.env` игнорируется: никогда не фиксируйте свой ключ.

Индексируйте документы и задавайте вопросы:

```баш

Python -m src.ingest # индексирует данные/сэмпл (или передайте другую папку)

Python -m src.query "ваш вопрос" # только retrieval: показывает верхние фрагменты

Python -m src.ask "ваш вопрос" # полный RAG: ответ с источниками

```

Первый запуск загружает модель встраивания (около 1,1 ГБ) из Hugging Face. После этого он загружается из локального кэша.

## Структура проекта

```

Src/

Models.py Класс данных Chunk, общий для всего конвейера

загрузчики/PDF, DOCX, XLSX загрузчики + load_document() диспетчер

Chunking.py разделение слов с перекрытием

Встраивание store.py, индексация и поиск ChromaDB

Ingest.py индексирует папку с документами

Только поиск query.py

Generate.py prompt building и вызов LLM

Ответ на вопрос в командной строке ask.py

Данные/образец/ небольшие публичные/образцы документов для тестирования

## Конфиденциальность

Полученные фрагменты отправляются поставщику LLM, который вы настраиваете. Не индексируйте конфиденциальные документы при использовании размещенного API и проверяйте условия использования данных вашим провайдером (бесплатные уровни часто позволяют использовать запросы для улучшения продуктов). Поместите личные файлы в `data/private/`, который git-ignored.

## Ограничения

- **Оценки пока нет. ** Качество изыска не было измерено по реальному набору вопросов.

- **Отсканированные PDF-файлы не поддерживаются** (без OCR): страницы без текстового слоя не производят фрагментов.

- **Изыск всегда возвращает k ближайших фрагментов**, даже если ни один из них не имеет значения. Модели поручено говорить, когда нет ответа, но список источников все еще может показывать несвязанные фрагменты.

- **Столы обрабатываются просто. ** Таблицы DOCX и строки Excel преобразуются в текст без понимания объединенных ячеек или формул.

- На данный момент поддерживаются только `.pdf`, `.docx` и `.xlsx`.
